# توثيق مشروع WASel - Backend

## 📖 نظرة عامة على المشروع (Project Overview)
مشروع **WASel** هو عبارة عن نظام خلفي (Backend) متكامل لمنصة توصيل طلبات (متعددة المتاجر)، مبني باستخدام **Spring Boot**. المنصة تخدم أربع فئات من المستخدمين: 
1. **العميل (Customer):** يستعرض المتاجر، المنتجات، ويقوم بعمل طلبات وتتبعها.
2. **صاحب المتجر/الموظف (Store Owner / Employee):** يدير المتجر، المنتجات، التصنيفات، ويستقبل الطلبات لمعالجتها.
3. **السائق (Driver):** يستقبل الطلبات الجاهزة للتوصيل ويقوم بتوصيلها للعملاء.
4. **مدير النظام (Admin):** يشرف على كامل المنصة، ويشاهد الإحصائيات، ويدير المستخدمين والمتاجر.

---

## 🛠️ التقنيات المستخدمة (Tech Stack)
تم بناء المشروع بالاعتماد على أفضل الممارسات البرمجية واستخدام التقنيات التالية:
* **Spring Boot (Java 17+):** الإطار الأساسي لبناء التطبيق.
* **Spring Data JPA & Hibernate:** للتعامل مع قاعدة البيانات وإدارة العلاقات بين الجداول (ORM).
* **Spring Security & JWT:** لحماية الـ APIs وعمل المصادقة (Authentication) والتفويض (Authorization) بناءً على الأدوار.
* **H2 Database:** قاعدة بيانات مضمنة (In-Memory) لتسهيل التطوير والاختبار.
* **Lombok:** لتقليل الـ Boilerplate code (مثل Getters, Setters, Builders).
* **Validation (Hibernate Validator):** للتحقق من صحة البيانات المدخلة في الـ DTOs.
* **BCrypt:** لتشفير كلمات المرور في قاعدة البيانات.

## 🏛️ البنية الهندسية (Clean Architecture)
تم تقسيم المشروع بناءً على الـ Layered Architecture لضمان سهولة الصيانة والتطوير:
1. **Controller Layer (`/controller`):** تستقبل طلبات الـ HTTP (REST APIs)، وتمررها لطبقة الخدمات، ثم تعيد الاستجابة المناسبة.
2. **Service Layer (`/service`):** تحتوي على الـ Business Logic الأساسي للمشروع (مثل حساب التكلفة، تغيير حالات الطلب، التحقق من الصلاحيات).
3. **Repository Layer (`/repository`):** واجهات (Interfaces) تتواصل مباشرة مع قاعدة البيانات عبر Spring Data JPA.
4. **Entity Layer (`/entity`):** الكيانات التي تمثل جداول قاعدة البيانات.
5. **DTO Layer (`/dto`):** كائنات تستخدم لنقل البيانات بين العميل (Client) والخادم (Server) لضمان عدم كشف كائنات قاعدة البيانات مباشرة، ولإجراء التحقق (Validation).
6. **Exception Layer (`/exception`):** معالجة الأخطاء بشكل مركزي (Global Exception Handling) لإرجاع رسائل خطأ واضحة وموحدة للـ Client.
7. **Security Layer (`/config`):** إعدادات الحماية وفلاتر الـ JWT.

## 🗄️ تصميم قاعدة البيانات (Database Schema & Entities)
يتكون المشروع من 13 كياناً (Entity) رئيسياً مترابطاً:
1. **User:** الجدول الأساسي الذي يحمل بيانات الدخول (البريد، كلمة المرور المشفرة، الدور `Role`).
2. **Customer:** يرتبط بـ User، ويمثل الملف الشخصي للعميل.
3. **Driver:** يرتبط بـ User، ويحمل حالة السائق (متاح، مشغول) والتقييم.
4. **Address:** عناوين العملاء لحفظ مواقع التوصيل المختلفة.
5. **Store:** بيانات المتاجر (الاسم، الوصف، رسوم التوصيل، الحالة: مفتوح/مغلق).
6. **StoreEmployee:** لربط الموظفين (بصلاحيات `STORE_EMPLOYEE`) بمتاجر معينة.
7. **Category:** تصنيفات المنتجات داخل المتجر (مثل: مشروبات، وجبات رئيسية).
8. **Product:** المنتجات المرتبطة بمتجر وتصنيف معين، مع إمكانية إيقاف توفرها.
9. **Order:** الطلب الأساسي، يرتبط بالعميل، المتجر، وعنوان التوصيل، ويحمل حالات الطلب المختلفة (PENDING, ACCEPTED, ...).
10. **OrderItem:** تفاصيل المنتجات داخل الطلب. **ملاحظة:** يتم حفظ سعر واسم المنتج كـ "Snapshot" لحفظ السجلات التاريخية حتى لو تغير السعر مستقبلاً في جدول المنتجات.
11. **Delivery:** سجل التوصيل، يربط الطلب بالسائق ويحتوي على أوقات الاستلام والتسليم.
12. **Review:** تقييم العميل للطلب (يتم تقييم المتجر والسائق وتحديث متوسط تقييماتهم تلقائياً).
13. **Notification:** نظام إشعارات داخلية لتنبيه المستخدمين بتغير حالات الطلبات.

## 🔒 الأمان والصلاحيات (Security & Authorization)
* **التسجيل والدخول:** أي مستخدم يقوم بالتسجيل (Register) يتم تشفير كلمة المرور الخاصة به. عند الدخول (Login) يتم التحقق وإصدار **JWT Token**.
* **الـ JWT Filter:** أي طلب (Request) قادم للـ API يمر عبر `JwtAuthenticationFilter` الذي يتحقق من صحة الـ Token ويستخرج الـ `UserEmail` لتحديد من هو المستخدم الحالي وصلاحياته.
* **الأدوار (Roles):** 
  * `CUSTOMER`: يمكنه الطلب، التقييم، وإدارة عناوينه.
  * `STORE_OWNER` / `STORE_EMPLOYEE`: يمكنهم إدارة منتجات المتجر وتحديث حالات الطلبات الخاصة بمتجرهم فقط.
  * `DRIVER`: يمكنه استلام طلبات التوصيل وتحديث حالتها.
  * `ADMIN`: يمتلك صلاحية مطلقة للاطلاع على جميع المتاجر، الطلبات، إحصائيات النظام، وإيقاف حسابات المستخدمين.

## 🚀 رحلة عمل النظام الأساسية (Main Workflows)

### 1. رحلة المتجر والمنتجات (Store Workflow)
* يقوم صاحب المتجر (STORE_OWNER) بإنشاء متجر، ثم إضافة تصنيفات (Categories) ومنتجات (Products).
* يمكنه تغيير حالة المتجر إلى (OPEN) ليبدأ في استقبال الطلبات.
* يمكنه إضافة موظفين (Store Employees) لمساعدته في إدارة المتجر.

### 2. رحلة الطلب والتوصيل (Order & Delivery Workflow)
1. **العميل** ينشئ طلباً جديداً (حالة: `PENDING`). النظام يحسب المجموع ويرسل إشعاراً للمتجر.
2. **المتجر** يقبل الطلب (حالة: `ACCEPTED`).
3. **المتجر** يبدأ بتجهيز الطلب (حالة: `PREPARING`).
4. **المتجر** يعين الطلب كجاهز (حالة: `READY`). يقوم النظام بإنشاء سجل توصيل (Delivery) وينتظر سائقاً.
5. **السائق** يرى الطلبات الجاهزة ويقبل الطلب. (حالة الطلب: `ASSIGNED`، حالة السائق: `BUSY`).
6. **السائق** يصل للمتجر ويستلم الطلب (حالة الطلب: `PICKED_UP`).
7. **السائق** يتحرك باتجاه العميل (حالة الطلب: `ON_THE_WAY`).
8. **السائق** يسلم الطلب للعميل (حالة الطلب: `DELIVERED`). يعود السائق للحالة `AVAILABLE`.

### 3. التقييم (Reviews)
* بعد أن يصبح الطلب `DELIVERED`، يمكن للعميل ترك تقييم (من 1 إلى 5) للمتجر والسائق.
* تقوم الـ Service تلقائياً بحساب متوسط التقييمات للمتجر والسائق وتحديث ملفاتهم الشخصية.

## 📡 أهم الـ Endpoints في الـ APIs

* **المصادقة (`/api/auth`):**
  * `POST /register`: تسجيل حساب جديد.
  * `POST /login`: الدخول والحصول على JWT.
* **المتاجر (`/api/stores`):**
  * `GET /`: عرض المتاجر المتاحة للجمهور.
  * `POST /`: إنشاء متجر جديد (للأونر).
  * `POST /{storeId}/products`: إضافة منتج للمتجر.
* **الطلبات (`/api/orders`):**
  * `POST /`: إنشاء طلب جديد (للعميل).
  * `PATCH /{id}/accept` - `/{id}/ready`: تغيير حالة الطلب (للمتجر).
  * `POST /{id}/reorder`: إعادة طلب سابق بنفس المنتجات (للعميل).
* **التوصيل (`/api/deliveries`):**
  * `GET /available`: رؤية الطلبات المتاحة للتوصيل (للسائق).
  * `PATCH /{id}/accept` - `/{id}/deliver`: دورة حياة التوصيل.
* **الإدارة (`/api/admin`):**
  * `GET /dashboard`: عرض إحصائيات النظام (عدد المستخدمين، الطلبات النشطة والمنتهية).

## 🛡️ معالجة الأخطاء والاستثناءات (Global Exception Handling)
تم بناء كلاس `@RestControllerAdvice` مركزي للتقاط جميع الأخطاء وإرجاعها بشكل نظيف وموحد بصيغة JSON (`ErrorResponse`)، ومنها:
* `ResourceNotFoundException`: يُرجع 404 Not Found (مثل: المنتج غير موجود).
* `BadRequestException`: يُرجع 400 Bad Request (مثل: المتجر مغلق، تغيير حالة غير مسموح).
* `ForbiddenException`: يُرجع 403 Forbidden (مثل: محاولة تعديل متجر لا تملكه).
* `DuplicateResourceException`: يُرجع 409 Conflict (مثل: إيميل مكرر).
* **Validation Errors**: يقوم بإرجاع قائمة بالحقول التي لم تجتز الشروط (`@NotNull`, `@Min`, إلخ).

## 🏃 كيفية تشغيل المشروع (How to Run)
1. تأكد من تثبيت **Java 17** فما فوق.
2. يمكنك استخدام Maven Wrapper الموجود في المشروع. افتح الـ Terminal في مسار المشروع واكتب:
   * **للويندوز:** `mvnw.cmd spring-boot:run`
   * **للماك/لينكس:** `./mvnw spring-boot:run`
3. سيعمل السيرفر على البورت الافتراضي `8080`.
4. قاعدة البيانات (H2) ستُحفظ في الذاكرة ومسار الكونسول الخاص بها هو: `http://localhost:8080/h2-console`
   * **JDBC URL:** `jdbc:h2:mem:waseldb`
   * **Username:** `sa`
   * **Password:** `password`
